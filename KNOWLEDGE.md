# Global Review Knowledge (Cross-Project Learnings)
## Engineering Anti-Patterns & Production Pitfalls
- **Filesystem Drift & Inconsistent Paths:** Directories referenced across documentation, skills, test suites, and `.gitignore` must maintain strict 1:1 naming consistency (e.g., `logs/` vs `review/`).
- **Windows Symlink Fragility:** Repositories relying on symlinks for multi-agent aliases (`.cursorrules`, `CLAUDE.md`) must provide direct file copy commands for Windows environments without Developer Mode enabled.
- **Submodule Misdirection:** Never document a directory as a Git submodule unless `.gitmodules` is formally configured and committed in the repository root.
- **NTFS Zone Identifiers in POSIX:** Always filter out Windows/WSL ADS artifacts (`*:Zone.Identifier`) via `.gitignore` and pre-commit cleanup scripts to avoid breaking tarballs, linters, and CI runners.
- **Dual-Gate Authorization Drift:** Never maintain parallel authorization gates (e.g., manual role-name allowlist + granular permission claims) across backend and frontend; keep granular permission claims as the single source of truth.
- **Optional Form Overrides & State Traps:** When a backend schema treats a field as an optional override with a dynamic system default, the UI must allow selecting "(default)" in both create and edit modes without making the override irreversible.
- **Eager HttpClient BaseAddress Resolution:** Never execute `client.BaseAddress = new Uri(options.Url)` unconditionally in `AddHttpClient` delegates when the target integration can be toggled off; empty strings throw `UriFormatException` during DI resolution even if the feature is unused.
- **SQL Server Enum Migration & Type Precedence Clash:** Never modify past dated migrations to alter enum columns from integer to text; queries comparing `WHERE Col = @Text OR Col = @Int` against an integer column fail with `Conversion failed when converting the varchar value` due to SQL Server type precedence.
- **Unbounded Bulk Insert Truncation:** Never stream unvalidated external CSV/API string payloads into fixed-width database staging tables via bulk copy without explicit field length boundary validation during parsing; truncated fields abort transactions before savepoints or trigger uncommittable transaction states.
- **Single-Shot Daily Batch Trap:** When batch jobs trap all exceptions to align failure reschedule with a fixed daily window, transient network/integration hiccups (S3 timeouts, SQL deadlocks) lead to 24-48h data staleness; critical batch schedules require bounded short-interval retries before deferring to the next daily cycle.
- **SQL Server Enum In-Place Type Migration:** When migrating SQL Server enum columns from integer to varchar/nvarchar, `ALTER COLUMN` preserves raw digits (`'0'`, `'1'`) instead of enum string labels (`'Open'`, `'Close'`); always include an explicit `UPDATE ... CASE` data conversion step.
- **Stale-While-Revalidate Fallback on Daily Batches:** In-memory caches wrapping once-per-day batch synchronization tables must return stale snapshots on transient database errors instead of failing open and spamming downstream integrations.
- **Potemkin Circuit Breaker Anti-Pattern:** Classes de resiliência instanciadas sem checagem prévia de execução (`canAttempt`) ou com estado isolado por thread/VU atuam como barreiras placebo, dando uma falsa sensação de estabilidade sem proteger o sistema.
- **Load Testing Retry Storm Amplification:** Testes de carga e estresse nunca devem habilitar retries agressivos com backoff longo em falhas 429/5xx por padrão; em condições de saturação, os retries multiplicam o tráfego e transformam a ferramenta de medição em um ataque de negação de serviço que mascara os limites reais do sistema.
- **Inverted Wildcard Prefix Trap:** When checking if a principal can delegate permissions/scopes, checking `scope != "*"` instead of `strings.HasPrefix(scope, "prefix.")` allows a namespace wildcard (`service.*`) to inadvertently match and delegate arbitrary external permissions across systems.
- **Fail-Closed Decorator Workload Elimination:** Authorization decorators or filters guarding protected resources (`denyIfManaged`) should check if the principal already possesses the override/manager permission before querying databases or iterating bulk collections, avoiding unnecessary N+1 roundtrips and transient 503 errors.
- **Hardcoded Database Context in Migration Scripts:** Never include explicit `USE [dbname]` statements inside schema/data migration scripts; hardcoding the database name breaks execution in containerized testbeds, CI/CD runners, and staging environments with alternate catalog names.
- **Unchecked Batch Retry Cascade & Thread Starvation:** Batch processors looping over queues synchronously must check circuit breaker/pause state inside the iteration loop; if an external downstream service is down, executing unbounded retries per item serializes failure timeouts (e.g. 50 items × 30s = 25 minutes), completely blocking background worker loops and starving worker threadpools.
- **Poison Pill Trap in Batch Workers:** Wrapping an entire batch `foreach` in a single `try/catch` causes a single malformed or non-recoverable record (poison pill) to abort the entire batch cycle repeatedly, starving healthy queue items behind it; batch loops must isolate individual item processing with fine-grained error handling.
- **Sync-over-Async Task.Run Deadlock/Starvation Risk:** Calling `Task.Run(...).GetAwaiter().GetResult()` in services with high throughput introduces extra threadpool hops and blocks worker threads synchronously, risking threadpool exhaustion under alert bursts.
- **Cache Write-Back Pipeline Poisoning:** Optimizations that write back or heal cached metadata on-the-fly inside ingestion or alerting pipelines must be wrapped in non-fatal exception boundaries; database timeouts on optional cache updates must never abort the primary alerting/processing transaction.
- **Hierarchical Path Node Extraction vs Terminal Element:** When traversing hierarchical paths (e.g. `logicalPath`) in cloud/backup APIs, never assume the target parent is strictly the terminal element (`LastOrDefault()`); always filter by explicit target object type (`LastOrDefault(n => n.ObjectType == "TargetType")`) to avoid fragility when APIs append intermediate or leaf elements.
- **Synthetic Mock Contract Divergence:** Unit tests validating third-party cloud/API payloads against hand-crafted synthetic mocks that invert API schema semantics (e.g. placing infrastructure host nodes in `logicalPath` when the provider returns them exclusively in `physicalPath`) generate 100% false-positive green CI runs while breaking in 100% of runtime production requests.
- **Alert Deduplication in Clustered / Multi-Node Workloads:** When alerts are deduplicated via composite keys (e.g. `eventId = entity + host`), the host must represent a stable cluster anchor (preferred node) while volatile execution nodes are conveyed in metadata/message bodies to prevent duplicate split-brain incidents.
- **Prohibition of Unsolicited External Publishing:** Code review findings and reports must strictly remain within local files in `.code-review/`; NEVER post comments or submit reviews to external platforms (GitHub PRs, GitLab, Jira) via CLI/API without direct, specific user instruction.
- **Example Configuration Secret Leakage & Silent Fallback Hijacking:** Example configuration files (`appsettings.example.json`, `.env.example`) must never contain real production or staging credentials; fallback mechanisms loading examples when local configuration is absent must strictly validate placeholders and fail-closed before network dispatch to prevent accidental load or attacks on protected environments.
- **Two-Phase Async Outbox Confirmation:** Systems integrating with asynchronous upstream outbox architectures (e.g. ITSM Hub -> Service Desk) must not mark local state as terminal or trigger downstream telemetry on the initial mutation acceptance HTTP 200; state transitions must be deferred to dedicated polling jobs that verify actual worker outbox processing.
- **Optimistic Concurrency Rowversion Trap on Multi-Field Updates:** When updating an entity with optimistic concurrency (`rowversion`/`Timestamp`), never split field updates across multiple SQL statements or invoke partial-update repository methods while mutating other entity fields in memory; rowversion checks cause sequential statements to fail (0 rows affected) or silently discard in-memory state. All mutated fields must be persisted in a single combined SQL statement.
- **Asymmetric Flapping State in Two-Phase Transitions:** When deferring terminal state transitions (e.g. `ClosedAt`) to asynchronous confirmation jobs, entity lookup methods searching for "active" records (`WHERE ClosedAt IS NULL`) will match records undergoing transition. Rapid state oscillation (flapping/re-opening) within this confirmation window leads to swallowed events or orphaned records unless the confirmation job validates the latest domain aggregate state before finalizing the transition or tracking intermediate transition states.
- **Sticky Residual Errors in Gateway Responses:** Gateways that aggregate asynchronous errors (`sync_error`) in query endpoints alongside terminal success states (`local_status: resolved`) from prior operations must not have those errors evaluated before terminal success states, which would falsely reject completed operations.
- **Object Spread Incompatibility in Legacy k6 / CI Runtimes:** Using ES2018 object spread (`{ ...obj }`) in k6 test scripts running under older containerized runners (e.g. `k6io/k6-action`) throws fatal `SyntaxError: Unexpected token` in babel/goja parsers; always use `Object.assign({}, ...)` for cross-version compatibility.
- **CI continue-on-error Masking Test Suite Execution:** Adding `continue-on-error: true` to test execution steps in CI workflows suppresses startup syntax errors and authentication failures, producing false-positive green builds while omitting artifact generation and reporting downstream.
- **CI PR Comment Reporter Path/Schema Drift:** CI workflows parsing test summary reports from hardcoded static paths (`k6-dev-smoke.json`) or expecting custom envelope schemas (`metadata.environment`) fail silently when test runners generate dynamic timestamped filenames or raw tool outputs, creating persistent "No report generated" status comments.
- **Domain Qualification vs Entity Open State in Async Transitions:** In asynchronous state reconciliation (e.g. ticketing confirmations), never use coarse-grained entity active flags (`IsOpen` / `status != Closed`) to deduce whether an entity re-opened during an async window. When the domain aggregate supports states that are active locally but ineligible for upstream synchronization (e.g. informational/non-incident severities), verify against the explicit integration eligibility threshold (`severity >= threshold`) to prevent re-opening upstream resources upon legitimate downgrades.
- **Cloud API Gateway Idle Connection Drop:** When consuming cloud API gateways with strict keep-alive idle timeouts (~60s), .NET `HttpClient` instances without explicit `SocketsHttpHandler` recycling (`PooledConnectionLifetime` / `PooledConnectionIdleTimeout`) attempt to reuse stale TCP sockets terminated by the remote peer, throwing `HttpRequestException: An error occurred while sending the request`.
- **Suppressed Semantic Success vs Downstream Guid.Parse Trap:** When mapping handled/suppressed external API responses (e.g. HTTP 400 Bad Request with known suppression payload) as semantic success (`hasErrors = false`, `id = null`), ensure downstream converters and mapping models that perform strict parsing (`Guid.Parse(source.id)`) are guarded by `!string.IsNullOrEmpty(source.id)` checks to prevent silent `ArgumentNullException` crashes.
- **Diff Indentation Bloat & Synthetic New Code Coverage Trap:** Wrapping large legacy execution blocks in `try/catch` or conditionals without method extraction alters the whitespace/indentation of dozens of pre-existing lines, converting them into "New Code" in SonarQube/diff analysis and artificially collapsing PR test coverage metrics below quality gate thresholds.
- **DataTables Server-Side vs Client-Side Export Silent Data Loss:** Activating `serverSide: true` in tabular grids without reconfiguring client-side export extensions (`excelHtml5`) silently exports only DOM rows of the current visible page rather than the full filtered dataset, causing silent data loss in user reports.
- **Concurrent Test Refactoring Conflicts:** When an upstream target branch unifies logic and moves unit tests to consolidated helper suites (e.g. `EventHandlerHelperTests`), downstream feature branches modifying those same tests in their original location must discard their legacy copies in favor of the upstream consolidation to prevent merge conflicts and duplicate test assertions.
- **Asymmetric Case-Sensitivity Across Pipeline Boundaries:** When ingest components filter payloads using case-insensitive lookups (`HashSet(StringComparer.OrdinalIgnoreCase)`) while downstream handler/domain components validate using case-sensitive lookups (`List.Contains()`), configured variations (e.g., lowercased identifiers) pass ingestion but are silently dropped as invalid at the execution boundary.
- **Explicit Empty List Configuration Overwrite Trap:** When binding configuration sections to settings classes, checking `list == null || list.Count == 0` to apply fallback defaults makes it impossible for operators to intentionally deactivate or disable a category via explicit empty array (`[]`); defaults must only apply when the section key is physically absent (`!section.Exists()`).
- **Windows Build Output Artifact Contamination:** Build configurations generating XML doc files (`JCWeb.Core.xml`) with absolute drive paths must be excluded via `.gitignore` to prevent machine-local file paths (`C:/...`) from leaking into Git branches and PRs.
- **DataTables Server-Side URL Length Truncation on IIS:** When activating server-side pagination with DataTables, passing the default full column metadata dictionary via GET query string exceeds the 2048-character IIS limit (HTTP 404.15); ajax adapters must project a minimal parameter payload.
- **Shared Modal Async State Overwrite:** In web views where a shared modal fetches item details asynchronously on click, slow network responses from a previously selected row will overwrite the modal of a subsequently selected row; ajax handlers must validate the active row ID or abort inflight requests before launching new ones.
- **Backend Page Size Clamping Drift:** Clamping `pageSize` in the backend (`Math.Min(length, MAX)`) without enforcing the same limit on frontend grid controls (e.g. DataTables `pageLines`) causes offset calculation divergence, rendering intermediate records completely unreachable to users.
- **Destructive Null Overwrites in Heterogeneous Upserts:** When synchronizing polymorphic or partitioned domain models (such as single-host standalone nodes vs multi-node clusters) via single upsert queries, never overwrite dimension columns unconditionally with incoming null values (`col = @col`). In external APIs where cluster nodes or secondary topologies return null for physical host properties by design, unconditional updates destroy verified cache data; enforce defensive updates (`col = ISNULL(@col, col)`).
- **Universal Hard Parse & Plan Cache Pollution:** Embedding variables directly into SQL queries via string interpolation or concatenation forces database engines (SQL Server, Oracle, PostgreSQL, MySQL) into repeated Hard Parses (re-compiling execution plans, generating unique plan hashes, saturating query/library cache memory, and causing latch/mutex contention under high concurrency); all variable input in data manipulation statements MUST strictly use bind variables / parameterized queries, reserving string formatting exclusively for static allowlisted structural identifiers (tables/columns) when dynamic schemas are strictly unavoidable.
